# 03 — Determinism

**Required reading before touching `src/core/`.**

---

## 1. Why

The simulation must produce identical results from identical seeds, on every browser
engine, forever. Four things depend on it:

1. **Testing.** Soak tests and economy sweeps assert on outcomes 20,000 ticks deep. That
   is only meaningful if the run is reproducible.
2. **Bug reports.** A player sees a hero behave strangely; they export
   `(seed, commandLog, tick)` and it reproduces exactly on your machine. For a game whose
   entire value proposition is emergent behaviour, this is close to essential.
3. **Balance.** `economy.spec.ts` sweeps configurations headlessly. Non-deterministic
   runs make the results noise.
4. **Future multiplayer.** Lockstep networking sends only commands and requires every
   client to simulate identically. Retrofitting determinism later means rewriting every
   calculation in the game. Building it in now costs almost nothing.

Point 4 is optional; points 1–3 are not. Even if this game never ships multiplayer, the
rules pay for themselves.

---

## 2. The problem with JavaScript floats

IEEE-754 double arithmetic in JavaScript is well-specified: `+`, `-`, `*`, `/` and
`Math.sqrt` are **correctly rounded** and identical across engines.

The transcendental functions are not. ECMAScript explicitly permits implementation-defined
precision for `Math.pow`, `Math.sin`, `Math.cos`, `Math.tan`, `Math.exp`, `Math.log`,
`Math.atan`, `Math.atan2` and `Math.hypot`. V8, SpiderMonkey and JavaScriptCore use
different implementations, and results can differ in the last bits.

One differing bit in a utility score flips one goal choice, which changes one hero's
path, which changes a kill, which changes the entire simulation. Divergence is not
gradual — it is total.

## 3. The rules

### Banned in `src/core/**`

```
Math.random     Math.pow      **  (operator)
Math.sin        Math.cos      Math.tan
Math.asin       Math.acos     Math.atan     Math.atan2
Math.exp        Math.log      Math.log2     Math.log10
Math.hypot      Math.cbrt     Math.sinh     Math.cosh     Math.tanh
Date.now        performance.now             new Date()
```

### Permitted

```
+  -  *  /  %          Math.sqrt        Math.abs
Math.floor  Math.ceil  Math.round       Math.trunc
Math.min    Math.max   Math.sign
&  |  ^  ~  <<  >>  >>>  |0
```

`Math.sqrt` is safe: IEEE-754 requires it to be correctly rounded, and ECMAScript
inherits that requirement.

## 4. The patterns

### 4.1 Curves instead of exponents

Utility considerations need response curves. `x ** k` is banned, so curves are
**256-entry `Uint16Array` lookup tables** generated at build time and interpolated with
arithmetic only.

```ts
// src/core/ai/curves.gen.ts — GENERATED by tools/gen-curves.ts, checked in
export const INVERSE_STEEP_BOLD = new Uint16Array([/* 256 entries, 0..65535 */]);

export function curve(table: Uint16Array, x: number): number {
  const c = x < 0 ? 0 : x > 1 ? 1 : x;
  const t = c * 255;
  const i = t | 0;
  const f = t - i;
  const a = table[i];
  const b = table[i < 255 ? i + 1 : 255];
  return (a + (b - a) * f) / 65535;
}
```

Trait weighting is **table selection plus blending**, not exponentiation. Each curve
family ships three variants — `TIMID` (exponent 0.5), `NEUTRAL` (1.0), `BOLD` (1.8) —
and a trait value picks two and lerps between them:

```ts
export function traitCurve(fam: CurveFamily, trait: number, x: number): number {
  if (trait <= 1) return lerp(curve(fam.TIMID, x), curve(fam.NEUTRAL, x), trait - 0);
  return lerp(curve(fam.NEUTRAL, x), curve(fam.BOLD, x), (trait - 1) / 0.8);
}
```

This is deterministic, faster than `Math.pow`, and easier to tune by eye.

### 4.2 Squared distances

```ts
// ✗  if (Math.hypot(dx, dy) < range)
// ✓
if (dx * dx + dy * dy < range * range) { … }
```

Call `Math.sqrt` only when a true magnitude is needed — usually just for display.

### 4.3 Direction tables instead of trig

```ts
// src/core/spatial/iso.ts
export const DIR8 = [
  { x:  1, y:  0 }, { x:  1, y:  1 }, { x:  0, y:  1 }, { x: -1, y:  1 },
  { x: -1, y:  0 }, { x: -1, y: -1 }, { x:  0, y: -1 }, { x:  1, y: -1 },
] as const;
```

Facing is derived by comparing `dx`/`dy` signs and magnitudes, never `atan2`.

### 4.4 One RNG, owned by the world

```ts
export class Rng {
  constructor(seed: number) { /* xoshiro128** state init */ }
  nextU32(): number { … }
  nextFloat(): number { return this.nextU32() / 4294967296; }
  nextInt(min: number, max: number): number { … }   // [min, max)
}
```

Never instantiate a second generator. Never call `Math.random`, not even for a visual
effect inside core — visual randomness belongs in `render/`, where it cannot affect
simulation state.

### 4.5 Stable iteration

Object key order and `Set`/`Map` insertion order are stable in practice, but insertion
order can itself vary if it derives from something non-deterministic. Where order
affects outcomes — target selection, damage resolution, flag claims — **sort explicitly
by entity id.**

```ts
const candidates = [...nearby].sort((a, b) => a.id - b.id);
```

### 4.6 Fixed tick order

The tick order in `docs/02-architecture.md` §2.2 is part of the contract. Reordering
systems is a determinism change even if every system is individually deterministic.

### 5.2 The hash

```ts
// src/core/hash.ts — FNV-1a over canonical state
export function hashWorld(w: World): number {
  let h = 0x811c9dc5;
  const mix = (v: number) => { h ^= v | 0; h = Math.imul(h, 0x01000193); };
  mix(w.tick); mix(w.treasury); mix(w.rng.snapshot());
  for (const e of w.entitiesInIdOrder()) {
    mix(e.id); mix(e.transform.x * 1000 | 0); mix(e.transform.y * 1000 | 0);
    mix(e.health?.hp ?? 0); mix(e.alive ? 1 : 0);
    mix(e.agent?.currentGoal ?? -1); mix(e.purse?.gold ?? 0);
  }
  return h >>> 0;
}
```

Positions are quantised to 1/1000 before hashing. That is not a tolerance — the
underlying floats are already bit-identical. It keeps the hash stable against harmless
precision in *display* interpolation leaking into a debug path.

### 5.3 CI

`tests/replay.spec.ts` runs on **Chromium, Firefox and WebKit** via Playwright, plus
Node. All four must produce the same hash at tick 10,000 for the golden seed.

Run it from milestone 1. If discipline slips, you find out that week rather than during
a playtest three months later.

## 6. Failure playbook

Determinism test fails. In order:

1. **Do not widen a tolerance and do not `.skip` the test.** The failure is real.
2. Binary-search the tick: hash every tick in both runs, find the first divergence.
3. At that tick, diff the two worlds entity by entity. The first differing entity is
   almost always the culprit.
4. Check, in this order of likelihood:
   - a banned function that slipped in via a helper outside `src/core/`
   - a `Math.random` in a content file
   - iteration over a collection whose order derives from insertion timing
   - a system reordered in the tick loop
   - a `Date`/`performance` call in a logging path compiled into the core
5. Add a regression test for the specific cause before fixing it.

## 7. Things that look like improvements but break this

| Tempting | Why it breaks |
|---|---|
| "Replace the LUT with `Math.pow` for clarity" | Different results per engine |
| "Add a small epsilon to the hash comparison" | Hides real divergence; the floats are exact |
| "Use `Math.random` for a purely cosmetic jitter in core" | Advances nothing but still diverges the RNG stream if shared, and tempts future reuse |
| "Sort by distance instead of id" | Ties resolve unstably |
| "Move economy to every tick for smoothness" | Changes tick order and every downstream value |
| "Use `Date.now()` for a cooldown" | Wall clock varies per machine and per pause |
