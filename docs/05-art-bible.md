## 1. Projection — decide once, never deviate

**2:1 dimetric.** Tile footprint **64 × 32 px**.

```ts
// src/core/spatial/iso.ts
export const TILE_W = 64, TILE_H = 32;
export const TILE_W_HALF = 32, TILE_H_HALF = 16;

export function worldToScreen(x: number, y: number) {
  return { sx: (x - y) * TILE_W_HALF, sy: (x + y) * TILE_H_HALF };
}

export function screenToWorld(sx: number, sy: number) {
  return {
    x: (sx / TILE_W_HALF + sy / TILE_H_HALF) / 2,
    y: (sy / TILE_H_HALF - sx / TILE_W_HALF) / 2,
  };
}
```

**Depth sort by `(x + y)`, tie-broken by entity id.** Never by screen Y alone, and never
by an unstable comparator — sort order is simulation state, not a rendering detail.
Multi-tile buildings sort by their front-most tile.

### Camera settings for any 3D-rendered asset

- Projection: **orthographic**
- Azimuth: **45°**
- Elevation: **30°** — the games convention, giving a slightly taller tile than true 2:1

In Blender: `camera.rotation_euler = (radians(60), 0, radians(45))`

*(True mathematical 2:1 is elevation 26.565°, i.e. `radians(63.435)`. We use 30°. Pick
one, write it in a constants file, and never mix. Inconsistent camera angles are the
single most visible defect in isometric games — far more noticeable than mediocre
sprite quality.)*

Light rig: key light fixed at azimuth 315°, elevation 50°, for every subject. A building
lit from a different side than its neighbour reads as broken even when it's beautiful.

## 2. Dimensions

| Subject | Size | Notes |
|---|---|---|
| Terrain tile | 64 × 32 | Diamond, no overhang |
| Unit | 32 × 48 | Anchor at bottom-centre, feet on tile centre |
| Small building (1×1) | 64 × 64 | Anchor bottom-centre |
| Medium building (2×2) | 128 × 112 | Guilds, marketplace |
| Large building (3×3) | 192 × 160 | Palace |
| Lair | 128 × 112 | |
| Flag | 24 × 40 | Plus a DOM-rendered gold label |
| Fog tile | 64 × 32 | Single alpha-ramped tile, tinted |

Anchors matter more than sizes. Every unit anchors at bottom-centre; every building
anchors at the bottom-centre of its front-most tile. Get this wrong and nothing lines up.

## 3. Animation

MVP ships **4 rendered facings, horizontally mirrored to 8**.

| Action | Frames | Rate |
|---|---|---|
| `idle` | 1 | — |
| `walk` | 4 | 8 fps |
| `attack` | 2 | 6 fps |

That is **7 frames × 4 facings = 28 per class**, versus ~200 for full 8-facing sets. At
32 × 48 px nobody notices, and it is the difference between an achievable art budget and
an abandoned project.

Death is a 200 ms alpha fade plus a ground decal, not an animation.

### Frame naming

```
{subject}_{action}_{facing}_{index}

warrior_walk_ne_02
ratkin_attack_sw_01
guild_warrior_intact
guild_warrior_construction
```

Facings: `n ne e se s sw w nw`. Only `ne e se s` are rendered; the rest are mirrored at
runtime by negative X scale.

## 5. Asset strategy — three stages

### Stage A — procedural placeholders (milestone 1, ~2 hours)

Every sprite generated by `tools/make-placeholders.ts`: class-tinted capsules with a
facing pip for units, flat-shaded isometric boxes for buildings, four-tone diamonds for
terrain.

**Do not skip this stage in favour of real art.** You will change sprite dimensions three
times during milestones 2–5, and each change is free when the art is a script rather
than a folder of PNGs. Placeholders are also consistent by construction, versioned as
text, and regenerable.

Stage A output is **shippable**. If the project stalls, it still looks intentional.

### Stage B — CC0 packs (milestones 4–6)

Kenney's isometric ranges are CC0 and internally consistent, which matters more than
individual sprite quality. OpenGameArt filtered to CC0/CC-BY fills gaps.

Expect **good coverage for tiles and buildings, poor coverage for multi-facing animated
characters** — that combination is genuinely rare in free packs. The 4-facing decision in
§3 exists partly because of this.

### Stage C — Blender pipeline (post-MVP, or milestone 7 if art matters early)

One `.blend` per subject, headless Python render, atlas-packed output. This is how the
genre's originals were made and it remains the cheapest route to a consistent set.

```bash
blender -b subject.blend -P tools/render-sprites.py -- --out public/atlas/src --facings 4
```

The script sets the camera per §1, renders every frame of every named action strip, and
writes files following §3's naming convention.

### On AI image generation

Useful for concept exploration and one-off decorative props. **Unreliable for a coherent
set** — it cannot hold a fixed camera angle and light direction across twenty buildings,
and it cannot produce registered animation frames. Do not build the pipeline on it.

## 6. Atlas

- Packed by `tools/build-atlas.ts` using `free-tex-packer-core`
- Max 2048 × 2048, trimming on, **2 px border** to prevent bleed
- Output: `public/atlas/game.json` + `game.png`, PixiJS format
- Emits `src/render/frames.gen.ts` — typed frame-name constants, so a typo in a sprite
  name is a compile error rather than an invisible missing texture
- Runs as part of `pnpm pregen` and before `pnpm build`

## 7. Render layers

Strict order, one PixiJS `Container` each:

```
1. terrain      RenderTexture chunks, 16×16 tiles, rebuilt on change only
2. fog          tinted tile overlay, three states
3. buildings    depth-sorted with units
4. ground FX    decals, blood, construction dust
5. units        sprite pool, depth-sorted with buildings
6. overlays     selection ring, health bars, damage numbers
7. flags        always on top, never occluded
```

Layers 3 and 5 share one depth-sorted list — buildings and units must interleave
correctly or heroes walk through walls visually.

**All text is DOM.** No Pixi text anywhere. React renders over the canvas; this keeps
fonts crisp, accessible, and free of atlas overhead.

## 8. Licensing gate

Every shipped asset is CC0, CC-BY, or self-made. No exceptions, no "probably fine".

`assets.manifest.json` records `{name, url, license, author, sourcePage, sha256}` for
every third-party asset. `tools/gen-credits.ts` builds `CREDITS.md` from it and **fails
the build** if any entry lacks a license field.

If you cannot confirm a license on its source page, do not add the asset.

This is not legal caution for its own sake — it is what lets you open-source or sell the
result later without an archaeology project.
